# Совместимость

Эта библиотека ориентирована в первую очередь на Linux и обеспечивает
исходную совместимость с API Apple-фреймворка Combine; на этой платформе
библиотека импортируется как `import LinuxCombine`.

## Матрица платформ

| Поверхность API | Linux | Darwin (исходная совместимость) |
|---|---|---|
| Базовые протоколы, все издатели и операторы, субъекты | ✅ | ✅ |
| Планировщики: Immediate, DispatchQueue, RunLoop, OperationQueue | ✅ | ✅ |
| Мосты Foundation: NotificationCenter, Timer, URLSession, кодировщики | ✅ | ✅ |
| `@Published` и `ObservableObject` | ✅ | ✅ |
| Интероп с async/await (`values`) | ✅ | ✅ |
| Издатели KVO | ❌ исключено | ❌ (продуктовое решение) |

Единственное исключение по design — KVO (механика рантайма
Objective-C без аналога на Linux). Всё остальное, что документирует
исходный DocC (321 тип, 1091 проверяемое объявление), реализовано и
проверяется автоматически.

## Поведенческий паритет

«Паритет» здесь доказан, а не заявлен:

- **Заимствованный набор тестов паритета OpenCombine** (более тысячи
  тестов, лицензия Apache-2.0, происхождение описано в
  `Tests/OpenCombineParityTests/README.md`) выполняется против этой
  библиотеки: любое поведение, отличающееся от эталона, ломает сборку.
- Поведения, для которых **эталона не существует ни у кого** (в
  OpenCombine их, например, нет: `CombineLatest`, `Merge`,
  `CollectByTime`), зафиксированы собственными тестами и описаны в
  регистре особенностей `docs/QUIRKS.md`, раздел §B.
- **Удивительные, но подтверждённые** поведения (то, что Apple делает
  неочевидным образом, пока вы не сверитесь с тестами) собраны в
  разделе §A того же регистра — например, `buffer(..., prefetch:
  .byRequest, ...)` запрашивает `.unlimited` в момент подписки.

## Известные отклонения и ограничения

| Позиция | Статус |
|---|---|
| Издатели KVO | не реализованы (см. выше) |
| Ожидания из `assertCrashes` | формально пусты под SwiftPM (вырезаются компилятором) — совпадение по падениям **не** утверждается |
| Пробелы DocC-документации | у ряда API нет страницы в DocC (`Optional.Publisher`, `Result.Publisher`, `comparison(areInIncreasingOrder:)` и другие) — подписи подтверждены через официальные места вызова и тесты паритета (раздел §C регистра) |
| `Publisher.combineIdentifier` | издатели не идентифицируемы; идентификаторы есть у подписчиков, подписок и отменяемых маркеров (совпадает с исходным API) |

## Замечания о тулчейне

- Сборка ведётся Swift 6.x в языковом режиме Swift 5; нулевое число
  предупреждений является шлюзом.
- Вывод `String(describing:)` для ошибок-перечислений содержит имя
  модуля — не сравнивайте текстовые описания ошибок в тестах,
  сопоставляйте образцы `Subscribers.Completion` (так поступают и
  примеры в этом издании).
- Отрисованные DocC-объявления скрывают `where`-ограничения
  расширений; ограничения в этой библиотеке получены из обхода
  документации и тестов паритета, а не из отрисованных страниц
  (раздел §C регистра).

## Вопросы и ответы

**Почему `buffer(..., prefetch: .byRequest, ...)` запрашивает
`.unlimited` вверх по потоку?** Потому что так делает оригинальное
API; поведение закреплено тестами истории запросов (раздел §A
регистра, позиция A17).

**Почему `output(at: -1)` приводит к прекращению программы?**
Официальный инициализатор `init(upstream:range:)` содержит
предусловие неотрицательности; отрицательные индексы попадают в него
через `output(at:)` — поведение подтверждено тестами паритета.

**Можно ли встроить эту библиотеку в проект под iOS?** API
исходно совместим с Apple Combine, но модуль называется
`LinuxCombine` (на Apple-платформах уже поставляется настоящий
фреймворк под именем `Combine`); проект существует для Linux и для
изучения.

**Куда сообщать о расхождении поведения?** Любое падение тестов
паритета — ошибка; всё, что описано в разделе §B регистра, —
известное, проверенное решение; менять его следует только вместе с
обновлённым эталоном.
